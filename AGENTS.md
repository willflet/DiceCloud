# AGENTS.md

DiceCloud is a Meteor 3.4.3 + Vue 3 character sheet. Runtime code is in `app/`; there is no root package manifest, so run JS commands from `app/`.

## Where things live

- `app/client/main.js` and `app/server/main.js` are the entrypoints. Meteor loads modules by side-effect imports, so new server services, methods, cron jobs and publications must be wired through these files (usually by adding to an existing `methods/index` import).
- `app/imports/api/` is shared client/server code; `app/imports/server/` is server-only; `app/imports/client/ui/` is the Vue UI. Use absolute `/imports/...` imports.
- Feature code for Campaigns, Aurora imports and the Rules Reference lives in `app/imports/api/{campaigns,aurora,rulesReference}` and `app/imports/server/{campaigns,aurora,rulesReference}`. Top-level `campaigns/` and `reference/` are documentation and build tooling, not runtime code.
- Characters are a `Creatures` record plus a tree of `CreatureProperties` documents using nested sets (`root`, `parentId`, `left`, `right`). The engine in `app/imports/api/engine` computes derived values into `CreatureVariables`; do not assume a property's stored values are already computed.
- Collection schemas use the wrapper at `app/imports/api/utility/SimpleSchema` (not npm `simpl-schema`). Property schemas go through `createPropertySchema` in `app/imports/api/properties/subSchemas/`.
- Methods generally use `mdg:validated-method` with rate-limit and permission helpers. Check ownership with `app/imports/api/sharing/sharingPermissions.ts`; never trust client-supplied ids for access.

## Commands

Run from `app/` unless noted.

- Install: `meteor npm install` (Meteor's bundled Node 22); `npm ci` also works with Node 22 per `engines`.
- Dev server: `meteor run --settings exampleMeteorSettings.json` (or `npm run serve` if a gitignored `settings.json` exists). App runs on `:3000`.
- Lint: `npm run lint`.
- Server tests: `npm run test:server` (one-shot, disposable DB, port 3001).
- Client + server tests: `npm test` (watch mode; stop it manually).
- `npm run typecheck` currently reports many pre-existing errors and is documented as not passing. Do not relax `tsconfig.json` to hide them; verify changes with tests and targeted checks.
- Docker tests, from repo root: `docker build --progress=plain --target test .` runs the importer and server suites. Add `--target runtime --build-arg SOURCE_REVISION="$(git rev-parse HEAD)"` for the deployable image.
- Fast URL tests, from repo root: `node --test deployment/test_url_paths.mjs`; Aurora adapter: `node --test deployment/test_aurora_adapter.mjs`.
- Python tests, from repo root: `PYTHONPATH=importer python3 -m unittest discover -s importer/tests -v`; `python3 -m unittest discover -s reference -v`; `python3 -m unittest discover -s deployment -p 'test_*.py' -v`.
- Browser tests, from repo root: `cd deployment/browser && npm ci && npx playwright install --with-deps chromium firefox`, then against a running stack set `DICECLOUD_TEST_URL` and `DICECLOUD_TEST_FIXTURE` and run `npm test -- --grep '<pattern>'`. Setup requires registration enabled; the fixture contains generated credentials and must not be committed.

## Testing gotchas

- Test files are not auto-discovered. Add imports to `app/server/tests.js` and/or `app/client/tests.js`; an unregistered test silently does not run.
- The browser suite drives a live deployment, not the Meteor dev server alone. It covers root and `/dnd/` prefix modes; restore checks need the retained fixture plus `DICECLOUD_VERIFY_RESTORE=1`.
- CI (`.github/workflows/runtime.yml`) runs Docker `test`/`runtime` builds and the browser suites; it does not run `npm run lint` or `npm run typecheck`.

## URL prefix contract

- `ROOT_URL` may include a path prefix (for example `https://host/dnd/`). Never hardcode a root-absolute app asset, API, account or cross-instance URL. Use `appPath`/`basePath` from `app/imports/api/utility/basePath`, or the helpers in `app/imports/api/utility/urlPaths.mjs`.
- Vue router paths stay application-relative; `withBasePath` intentionally leaves external `http(s)`, `//`, `mailto` and fragment links alone.
- `urlPaths.mjs` is copied by itself into the runtime image and imported by deployment scripts. Keep it dependency-free and run `node --test deployment/test_url_paths.mjs` after changing it. Full rules: `deployment/URL-PATH.md`.

## Generated and sensitive files

- `app/imports/parser/grammar.js` is generated from `grammar.ne`: from `app/imports/parser/`, run `meteor npx nearleyc grammar.ne -o grammar.js`; do not hand-edit the output.
- `app/private/rules-reference/srd51.json` is generated by `python3 reference/build_srd51.py` from `reference/srd51/`; do not edit it directly. Verify with the `reference/` tests.
- `deployment/bundle-package.json` and `deployment/bundle-npm-shrinkwrap.json` deliberately replace vulnerable versions in Meteor's generated server bundle. Keep them in sync rather than deleting them.
- Never commit `app/settings.json`, `runtime.env`, secrets, test fixtures/credentials, `fileStorage/` or backups. Private deployment config comes from `python3 deployment/initialize.py --directory ...` and is intentionally mode-restricted.

## Data and deployment safety

- Use `deployment/operations.py` for backups/restores; do not copy live Mongo files. Restores require a fresh `dicecloud-restore-*` Compose project, fresh credentials and volumes; never rename a live project to bypass guards.
- The default deployment runs one app process with registration disabled and the app bound to `127.0.0.1`; Mongo is not exposed. Do not run destructive `docker compose down -v` against a real project.
- If a change requires transforming stored documents, add a `percolate:migrations` migration under `app/imports/migrations/server/` and bump `app/imports/constants/SCHEMA_VERSION.js`. A database/version mismatch puts the app into maintenance mode.
- Read `deployment/README.md`, `deployment/URL-PATH.md`, `importer/README.md` + `CONTRACT.md`, `campaigns/README.md` and `reference/README.md` before changing those areas. `SERVE.md` is a host-specific WSL/Windows runbook.

## Style

- ESLint enforces single quotes, Vue `script` / `template` / `style` block order, and exhaustive switches. No formatter is configured; match surrounding formatting and avoid reformatting unrelated files.
- The importer is MPL-2.0 and `reference/` contains CC-BY-4.0 SRD material. Preserve the corresponding `NOTICE` and attribution files.
